WHAT WAS DONE
-------------
Scanned all four AppWare project folders (AppWare Auth, Hungry, Roomies, Jukebox)
and read every existing SQL file, .env file, CLAUDE.md, AppWareAuthIntegration.md,

WHAT THE SQL FILE DOES
----------------------
1. WIPES all existing AppWare tables (destructive — in Phase 0)
2. Recreates everything cleanly with no conflicts

Key architecture decisions:
  - public.profiles           — Unified account for all 3 apps (merged all fields)
  - public.households         — Shared between Hungry AND Roomies (same concept)
  - public.friendships        — Unified using Jukebox model (status: pending/accepted/blocked)
  - public.household_members  — Single junction table replacing old patterns
  - public.cross_app_activity — NEW: cross-app signal bus powering all ecosystem features

New tables in the unified schema vs previous per-app schemas:
  - meal_plans, meal_plan_recipes    (Hungry smart meal prep persistence)
  - chef_history, chef_history_photos (Hungry cook log with soundtrack field)
  - potluck_items, potluck_claims    (Hungry household event coordination)
  - cross_app_activity               (AppWare ecosystem signal bus)

New columns added to profiles:
  - hungry_tutorial_done, has_completed_roomies_tutorial  (tutorial state flags)
  - jukebox_onboarding_done, jukebox_tutorial_done        (Jukebox onboarding)
  - vibe_tags (jsonb)           — Jukebox genre/focus/era profile
  - favorite_genres (text[])    — cross-app playlist seeding
  - hungry_settings (jsonb)     — dietary restrictions, nutrition goals, budget, etc.

New columns on other tables:
  - chef_history.soundtrack (jsonb) — track playing when meal was cooked
  - chores.difficulty (int 1-5)     — BPM hint for Chore-Sync Anthems

Storage buckets:
  - roomies-property-vault  (Roomies property documents)
  - chef-history-photos     (Hungry cook log photos)
  - user-avatars            (Global profile pictures)

Realtime enabled on:
  shopping_list, fridge_inventory, shopping_items, messages, now_playing,
  user_presence, notices, chore_assignments, potluck_items, potluck_claims,
  cross_app_activity


HOW TO RUN THE SQL
------------------
1. Go to: https://supabase.com/dashboard/project/wshadsznycwugowiexmy/sql/new
2. Open appware_unified_schema.sql from this folder
3. Copy the ENTIRE file contents
4. Paste into the SQL Editor and click Run (▶)

⚠  The script drops all existing tables first. If you have live users with data
   you want to keep, export/backup before running.

ECOSYSTEM FEATURES IMPLEMENTED
-------------------------------
All features use cross_app_activity as a signal bus. The "write" side is in each
app; the "read" side is also implemented where feasible in code.

  #1  Kitchen Concert        — CookingMode → cross_app_activity 'cooking_started'
                               with genre_seed mapped from cuisine
  #2  Chore-Sync Anthems     — Chores.tsx → 'chore_completed' with BPM hint from
                               chore.difficulty
  #3  Smart Grocery Split    — When pantry item with price is shared to household,
                               auto-creates a Groceries transaction in Roomies
  #4  Potluck Planner        — HouseholdTab fetches member dietary restrictions and
                               generates filtered item suggestions; writes
                               'potluck_created' signal for Jukebox playlist
  #5  Eco-Vibe Analytics     — AppWare Wrap tab in Hungry analytics: shows monthly
                               recipes cooked, chores done, bills paid, top cuisine,
                               pantry worth, and currently playing on Jukebox
  #6  Mood-Food Matching     — Jukebox writes mood signal; Hungry reads it and
                               pre-selects matching mood filter in recipe explorer
  #7  Grocery Gig Status     — PersonalShopper sets user_presence to "🛒 At the
                               Store"; HouseholdTab shows banner when any member is
                               detected at a store
  #8  Victory Fanfare        — Chores.tsx writes 'all_chores_done' when last pending
                               chore is completed
  #9  Concert Fund Tracker   — useWishlist syncs to Supabase; detects matching
                               household wishlists and writes 'concert_fund_suggested'
 #10  Late-Night Snack Mode  — Jukebox writes 'late_night_active' when playing after
                               11pm; Hungry pre-selects "late_night" mood filter
 #11  Grocery Gig Status     — see #7
 #12  Soundtrack of My Life  — Queries now_playing table when marking a recipe as
                               cooked; saves track in chef_history.soundtrack
 #13  Rent-Day Rewards       — Finance.tsx writes 'all_bills_paid' when all debt
                               splits are settled
 #14  Nutritional BPM        — Hungry writes nutrition_shortfall signal; Jukebox
                               HomeScreen reads it and shows workout playlist banner;
                               Roomies Chores sorts high-difficulty chores first


APIs YOU NEED TO INTEGRATE
--------------------------
The following external API integrations are required to unlock full functionality
of certain features. The database and code signal infrastructure is already in place.

1. SPOTIFY AUDIO FEATURES API
   Required for: #2 (Chore-Sync Anthems), #6 (Mood-Food Matching), #14 (Nutritional BPM)
   What it does: Returns valence, energy, danceability, tempo (BPM) for any track.
                 Currently the code uses time-of-day heuristics as a proxy.
   How to set up:
     - In Jukebox .env: EXPO_PUBLIC_SPOTIFY_CLIENT_ID already set (a2e2a9cac6e34fc9...)
     - Request the 'user-recently-played' and 'user-top-read' OAuth scopes
     - Call: GET https://api.spotify.com/v1/audio-features/{id}
     - Endpoint reference: https://developer.spotify.com/documentation/web-api/reference/get-audio-features

2. GOOGLE PLACES API (or Foursquare Places API)
   Required for: #7 (Who's Home? Shopping Alerts) — to detect when a user is
                 physically at a grocery store using GPS coordinates.
   What it does: Reverse-geocodes coordinates to identify nearby POIs by type
                 (e.g., 'grocery_or_supermarket').
   How to set up:
     - Create a Google Cloud project → enable Places API
     - Set VITE_GOOGLE_PLACES_KEY in Hungry's .env
     - Call: GET https://maps.googleapis.com/maps/api/place/nearbysearch/json
             ?location=LAT,LNG&radius=100&type=grocery_or_supermarket&key=KEY
   Note: Browser Geolocation API (navigator.geolocation) is already in place in
         PersonalShopper.jsx — only the store-type lookup requires Google Places.

3. APPLE SIGN-IN — see "WHAT COULD NOT BE IMPLEMENTED" section below.
   Requires a paid Apple Developer Program membership ($99/year) before any
   credentials can be generated. Not a code change — a purchase prerequisite.


WHAT COULD NOT BE IMPLEMENTED (REQUIRES PAYMENT, PURCHASE, OR NATIVE CAPABILITIES)
-------------------------------------------------------------
These features are architecturally supported via cross_app_activity signals in the
database, but their full execution requires native iOS/Android capabilities that
are not available in web apps. They remain ready to implement when the apps ship
as native builds.

0. APPLE SIGN-IN (Sign in with Apple)
   Requires: Apple Developer Program membership — $99/year at developer.apple.com/programs/enroll/
   Once paid:
     - Apple Developer Console → Certificates, Identifiers & Profiles
     - Create a Service ID (e.g., com.appware.auth)
     - Create a .p8 private key under "Keys"
     - Supabase Dashboard → Authentication → Providers → Apple
       → paste Service ID, Team ID, Key ID, and .p8 contents
   All the app code already supports Apple OAuth via Supabase; only the
   credentials are missing.

1. GEOFENCING (Feature #7 — Who's Home? Shopping Alerts)
   The signal infrastructure is built: cross_app_activity receives location events,
   and HouseholdTab shows the At-the-Store banner. However, automatic background
   geofence detection (triggering when the user enters a store radius without
   opening the app) requires:
     - iOS: CoreLocation CLLocationManager with region monitoring
     - Android: Google Play Services Geofencing API
   These are not available in a web PWA. The current fallback is: the banner
   activates when the user manually opens Personal Shopper mode.

2. iOS LIVE ACTIVITIES / DYNAMIC ISLAND (Hungry Cooking Mode)
   Showing the current recipe step on the lock screen or in the Dynamic Island
   while Cooking Mode is active requires the ActivityKit framework (iOS 16.2+).
   Not possible in a web app. Requires a native Swift UI extension.

3. PUSH NOTIFICATIONS — BACKGROUND DELIVERY
   The Supabase realtime subscription for cross_app_activity delivers signals
   while the app is open. Background push notifications (e.g., "Your spinach
   expires tomorrow!", "Omkar is at Whole Foods") require:
     - Web: Push API + a service worker (partially feasible in the PWA)
     - Native: Expo Notifications (already set up in Jukebox via push_token
       in drop_reminders table) — extend this pattern to other signal types
   The drop_reminders table already stores push_token per user — use that
   infrastructure to send cross_app_activity push notifications.

4. APPLE MUSIC / MUSICKIT INTEGRATION (Jukebox)
   Full Apple Music integration (playback, library access, now-playing sync)
   requires MusicKit JS (web) or MusicKit on iOS. Currently shows "Coming Soon."
   MusicKit requires an Apple Developer membership and a MusicKit key.

5. INSTAGRAM GRAPH API (Jukebox Social Sync)
   Connecting Instagram to sync friends from the user's follower/following list
   requires Instagram Graph API access, which requires:
     - A Facebook/Meta Developer App with instagram_basic permission
     - App review approval from Meta for production use
   Credentials: EXPO_PUBLIC_INSTAGRAM_APP_ID and SECRET in Jukebox .env
   are already placeholder-set.

6. VENMO DEEP-LINK SPLITS (Hungry + Roomies)
   Direct Venmo payment requests (beyond the deep-link URL already implemented
   in HouseholdTab) require the Venmo API (restricted to approved partners).
   The current Venmo link opens the Venmo app with amount/note pre-filled.
   For full API integration: apply at https://venmo.com/api/

7. PANTRY PROXIMITY — STORE AISLE ROUTING (Feature #7 extension)
   The feature where items in the shopping list are ordered by physical store
   aisle position (routing optimization) requires:
     - A store floor plan API (Kroger, Instacart, or proprietary) OR
     - Bluetooth beacon infrastructure inside the store
   The current STORE_AISLES map in PersonalShopper.jsx provides a static
   approximation; dynamic routing requires store-specific APIs.

8. SMART SPEAKER INTEGRATION (Feature #8 Victory Fanfare, Feature #13 Rent-Day)
   Playing a "Victory Song" on household speakers when all chores are done
   requires integration with:
     - Spotify Connect API (control active Spotify device)
     - Google Cast SDK
     - Apple AirPlay 2
   The signals are already written to cross_app_activity — the playback trigger
   can be wired when one of the above APIs is integrated.
